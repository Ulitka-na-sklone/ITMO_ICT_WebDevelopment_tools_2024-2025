Модуль URL Парсера

Обзор

Задачи Celery для асинхронного парсинга веб-страниц с использованием внешнего сервиса парсера.

Конфигурация

Зависимости

  • Celery: Распределенная очередь задач
  • HTTPX: Асинхронный HTTP клиент
  • Redis: Брокер сообщений и бэкенд для результатов

Сервисы

  • Redis: redis://redis:6379/0
  • Сервис парсера: http://parser:9000/parse

Задачи

parse_url

Парсит один URL адрес.

Параметры: - url (str): URL для парсинга

Возвращает: - JSON ответ от сервиса парсера или объект ошибки

Использование:

parse_url_tasks.delay("https://example.com")

parse_all_urls

Парсит все URL из предопределенного списка.

Возвращает: - Массив результатов парсинга для каждого URL

Использование:

parse_all_urls.delay()

Внутренние функции

_parse_url(url: str)

Асинхронная функция, которая: 1. Получает HTML контент по URL 2. Отправляет HTML в сервис парсера 3. Возвращает распарсенные результаты

Особенности: - Следует за редиректами - Использует заголовок User-Agent Mozilla - Обработка исключений с возвратом ошибки

_parse_all_urls()

Асинхронная функция, которая обрабатывает все URL последовательно из списка urls.

Предопределенные URL

urls = ["https://stackoverflow.com/users"]

Обработка ошибок

Возвращает структурированный ответ об ошибке:

{
  "error": "Сообщение об ошибке",
  "url": "https://failed-url.com"
}

Пример ответа

Успешный парсинг возвращает ответ от сервиса парсера:

{
  "title": "Заголовок страницы",
  "content": "Распарсенный контент",
  "metadata": {...}
}
